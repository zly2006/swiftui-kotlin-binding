# 项目目标与完成标准

本文件定义 `swiftui-kotlin-binding` 的通用库目标与验收要求。包名前缀为 `me.zly2006`。

## 目标

任何开发者都可以直接使用 Kotlin、Compose 库及其声明式语法编写 Apple 原生 UI。库应完整表达官方原生组件、布局、视觉效果、动画、交互、无障碍和生命周期能力，并保留原生 UI 按需渲染、低 CPU 和低内存占用的优势。

Kotlin 负责 UI 声明、布局意图、视觉参数、状态、事件决策和应用行为。Swift 仅将逐项调用接到官方原生 API，不包含应用页面、业务逻辑、自绘控件或设计参数。组件的实际绘制、平台内部交互与原生动画执行由官方框架承担。

外部应用的 UI mock 用于兼容性、像素一致性和性能回归测试，不属于库本身。只支持少数控件、做出一个示例窗口或复刻一个页面，都不足以证明通用库目标完成。

## 可直接使用

开发者应能按公开文档添加发布依赖、导入 API 并运行示例，不需要复制仓库源码、修改本机绝对路径、手写 Swift 页面或自行补齐 ABI。文档必须说明平台、最低系统版本、Kotlin/Compose 版本、原生链接与打包要求，以及各 API 的适用范围。

macOS 是当前已有代码的验证起点。库的最终覆盖范围包括 Apple 原生 UI 能力在不同目标平台上的可用性差异；不能把单一架构或单一系统上的演示当成通用库已经完成。

## 原生能力覆盖

覆盖清单从关键组件白名单起步，依据 Apple 官方文档确定常用组件、布局、样式、效果和交互，再用开源应用实际用法补齐缺口。只为实现这些能力选取必要的属性、重载、modifier 和原生调用，并记录系统及平台 availability；不要求导出每个 SDK 符号或为每个函数生成绑定。白名单与依据见 [component-whitelist.md](component-whitelist.md)。

每项能力必须区分已列入、已生成、已编译、已验证、需要语义适配和尚未支持。真实应用出现未支持的 UI 需求时，要补充白名单或用已有原生能力组合实现，不能静默忽略。控件数量和生成代码数量都不能代替能力与行为验收。

重复绑定代码采用构建期生成，结果为明确、有类型的 Kotlin 调用和独立原生接口。生成器只处理白名单中的必要绑定，运行时不得发送 JSON 页面、字符串命令或组件树协议。

## 原生渲染与资源占用

渲染路径使用官方原生 UI，由 Compose Runtime 和编译器管理 Kotlin 组合、状态与重组。停用的 Compose/Skia 混合实验已经删除，不保留另一套渲染架构。

静止界面不得因为库的宿主、轮询或自定义渲染时钟而持续刷新。属性更新应只影响相应原生节点；不能通过重建整个页面或为每个控件建立独立渲染宿主来掩盖缺失的更新机制。回调、资源持有和释放必须有明确的所有权与线程约束。

性能结论必须来自同一设备、系统、数据、窗口尺寸和交互负载下，与等价原生实现的真实对照。至少报告静止、滚动、动画、频繁状态更新、后台和窗口卸载场景的 CPU、内存、帧表现、分配与资源释放情况。先测量原生基线，再设定可核验的回归门槛；“使用了 Kotlin/Native”或“没有 JVM”不构成低占用证明。

## 完成验收

- 发布依赖和最小示例可以在独立消费项目中直接使用，公共 API 与版本兼容性有文档和检查。
- 关键组件白名单及真实应用查漏记录可复现，公开范围内的能力有编译和行为证据，未支持项明确列出；无需全量 SDK 导出。
- Kotlin 与 Swift 的责任边界得到源码与依赖检查，纯 Kotlin UI 不需要平台指针或 Swift 业务代码。
- 代表性原生 UI 的布局、视觉、输入、焦点、无障碍和生命周期行为经过真实运行验证。
- 外部 UI mock 使用原控件对应的绑定，在相同条件下完成逐像素对比；100% 一致必须以全部像素无差异的证据支持。
- 与等价原生实现的资源和帧表现对照通过已确定的性能门槛，且静止、后台、更新和卸载没有额外持续负载或泄漏。

当前以上完成条件均未被整体证明。白名单生成器与原生运行时已有实现；不能把部分绑定、页面截图或构建结果当成全覆盖和性能验收已经完成。
