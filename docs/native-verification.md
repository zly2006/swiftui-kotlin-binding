# 白名单生成与原生运行时验证

2026-10-04 在 macOS 26.6.2、Apple Silicon、Xcode 26.6 和 arm64 JDK 21 上验证。项目使用 Kotlin 2.4.0、Compose Runtime 1.11.1 和 coroutines 1.11.0。

## 生成边界

生成器只处理 [关键组件白名单](component-whitelist.md) 中的适配定义。目前输出 48 项绑定，包含一个内部根节点、原生组件、容器和必要 modifier，不代表 48 个完整控件，也不代表所有原生能力已经支持。

全量 SDK 审计命令与解析依赖已移除，约 512 MB 的全量符号图已删除。研究材料只保留几个官方文档页面和代表性开源源码的本地核读副本，位于忽略的 `work/` 中。

## 编译与测试

| 检查 | 证据与结果 |
| --- | --- |
| 白名单筛选 | 未入名单的定义不会生成；白名单缺少适配时明确失败。 |
| 可重复生成 | 两个独立输出目录逐文件内容一致，C 创建入口数量与选中绑定数量一致。以上共 3 项生成器测试通过。 |
| Compose 原生接入 | 2 项 JVM 测试通过，覆盖状态更新不重建、最新回调、静止不请求帧、带 key 的子节点移动，以及移除和关闭只释放一次。 |
| 原生编译 | 所选 Swift API、cinterop、Kotlin/Native 运行时与可执行文件编译成功；纯 Kotlin UI 的 JVM 编译成功。 |
| 历史实验 | 旧的混合宿主和手写绑定现已删除，对应测试不再维护。历史测试与截图不作为当前架构验收证据。 |
| 原生依赖 | `samples:native-macos` 的 macosArm64 编译依赖只有 Compose Runtime，未发现 Compose UI 或 Skiko/Skia 依赖。 |

构建后的独立应用为 `samples/native-macos/build/NativeDemo.app`，约 9.5 MB，包含原生动态库，签名校验通过。可执行文件使用包内相对 rpath，不依赖工作目录中的动态库位置。

## 真实窗口

`scripts/verify-native.sh` 对最终应用包执行浅色和深色的初始、更新、卸载三个状态，共 6 组检查通过。窗口仅置于后台，不激活应用；截图只采集本任务窗口。六张最终截图均已目视检查。

初始界面创建 30 个原生节点，整棵界面只有一个 NSHostingView。更新按钮、Toggle、TextField 和 Slider 的回调之后，创建数量仍为 30，原生属性更新 5 次，SwiftUI 节点 body 求值从 30 增至 35。卸载输入与显示组件后，Kotlin 存活节点降至 16，释放 14 个节点。

每个场景在稳定后继续等待两秒，Compose 请求帧数、原生属性更新数和节点 body 求值数均未增加。这证明本场景中没有库自身的持续重组或空帧调度，不能替代 CPU、内存与等价原生实现的性能对照。

窗口关闭后，Kotlin 节点所有权全部释放。根宿主仍受 Kotlin/Native 的 Objective-C 包装引用影响；测试在退出窗口作用域并显式回收互操作引用后检查，原生节点和宿主均为零。日志保留了回收前后的数量，未将作用域内暂存的根宿主误报为即时析构。

本轮回调检查调用与官方控件共享的原生 relay，并验证 Kotlin 受控状态和实际画面更新；没有注入系统鼠标或键盘事件，因此完整用户输入、焦点与无障碍行为仍待验证。

## 尚未完成

当前窗口是库的诊断示例。外部 UI 的完整迁移与像素验收、原生 CPU/内存性能对照、白名单待补组件、独立消费项目和正式发布均未完成。项目目标仍按 [project-goal.md](project-goal.md) 继续推进。

## 代码清理后的验证

停用的 Skia 混合模块、旧示例、四类手写组件桥与其测试已经移除。`swiftui-bridge` 现在只提供 macOS C 互操作与 Swift 原生桥；`swiftui-compose` 的公共部分和 JVM 测试不再依赖它。当前模块职责见 [modules.md](modules.md)。

清理后重新运行了 3 项生成器测试、2 项 Compose Runtime 接入测试、纯 Kotlin UI 的 JVM 编译和 macOS 可执行文件链接，全部通过。使用新编译的可执行文件采集本任务窗口后，1272×600 的首页与保留参考图逐像素一致。该检查仅用于确认清理没有改变已验证画面，不扩大其他状态的验收结论，也没有改写用户正在运行的应用包。
